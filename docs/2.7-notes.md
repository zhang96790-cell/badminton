# Skyline Smash 2.7: notes

## Audit (the game as of 2.6)

- **Ratings.** Stored in Supabase `profiles.rating` (start 1000), with `wins`/`losses`. Ranked results are written
  only by the room server through the service-only RPC `record_match` (fixed K = 32, 400-divisor expectation,
  floor 100). Tiers are client-side only (`src/rating.ts`): Bronze <900, Silver 900, Gold 1100, Platinum 1300,
  Champion 1500.
- **Quick match format.** 1 game to 21 (set by the matchmaker in `server/src/index.ts` `setupRanked`). Unchanged in 2.7.
- **Matchmaking.** `server/src/matchmaker.ts`: gap starts ±100, widens 25 rating/s, up to ±800. Unchanged (owner's choice).
- **Gameplay constants** (`src/config.ts`): reach 1.15 m (+0.1 for people), swing wait after a hit 0.45 s
  (`SWING.hitRecovery`), perfect timing 0.14 s after the press (`SWING.idealDelay`, window ±0.08 s), lift angle 57°
  (65° from the net), smash speed from `SHOTS.maxSpeedByHeight`.
- **Online flow.** The host's screen decides points and sends `point` (numbered with `n`); the guest's screen
  reports landings on its side (`land`). A guest waiting too long sends `sync {n}`; the host resends the last point
  or sends `resync` (replay the point as a let). Messages during a blip are held and resent. Version check: each
  page sends its version (`v`) when joining; a mismatch shows a Refresh button. Reloading mid-match resumes from the
  room's match snapshot (`resumeReq`/`resume`).
- **What the worker tracks about connections.** Per room seat: connected/away, `awaySince`, drop count. No global
  presence before 2.7 (the only "online" signal was `profiles.last_seen`, set by a 60 s heartbeat RPC).
- **Sim harness.** In-page scripts (run in the dev preview) that create `Game` objects with `AIController`s and
  fake room links; nothing checked in.

## Owner's decisions for 2.7 (asked before building)

| Topic | Decision |
|---|---|
| Characters | Build the system now, neutral: only the "Club Player" placeholder (all 20s), so play is identical until players are added. |
| Elo | Keep K 32; add the margin factor 0.9–1.15 (share of points won). No new-player or high-rating K. |
| Tiers | 8 tiers: Rookie <900, Club 900, Regional 1050, National 1200, International 1350, Elite 1500, World Class 1700, Legend 1900; 20-point demotion buffer. |
| Seasons | Quarterly; Season 1 ends 31 Dec 2026 (UTC); soft reset 1000 + 0.5 × (old − 1000); season leaderboard; titles and card frames. |
| Friend rooms | Host chooses Elo or Non-Elo; Elo friend matches count 0.75×; at most 3 per day per pair, then Non-Elo. |
| Matchmaking | Keep today's range. (So no practice-while-waiting rally.) |
| Fair play | Both screens confirm the final score (disputes change no rating); reconnect window 40 s. No queue bans. |
| Stamina | No fatigue in 2.7; the stat exists but does nothing yet. |

Already built before 2.7, so not rebuilt: ping in lobby and HUD, rejoin after a reload, no penalty when the other
player's connection is the cause (2.5.8), rematch / Queue again, 6 preset chat phrases, the version check.

## Defaults chosen (not covered by the spec or the owner)

- **Placeholder player.** "Club Player" (`default_player`), country `XXX`, every stat 20. Everyone owns it; it can't be
  disabled. Neutral stats are exactly the old game (every multiplier is 1).
- **Net-spin is not touched by stats.** The spec allowed Net to change accuracy and timing windows only; scaling the
  net-spin chance would change a threshold, so Net affects net-shot aim and the net-shot timing window only.
- **Fast-shot timing uses flight time,** not speed (pushes and clears travel at similar speeds; pushes arrive sooner).
- **Existing players** keep their rating; their tier is worked out from it, and anyone already above Regional gets the
  unlock picks for each tier they've passed.
- **Season leaderboard** shows players who've played a rated match this season; until anyone has, it shows everyone.
- **Friend rooms count for rating** only if the host turns it on and both players are logged in as different
  accounts. The login is sent to the room server as a message after joining (never in the URL), checked with the
  account server, and never passed on to the other player. The game only sends it once it sees a 2.7 room server.
- **Score confirmation.** The guest's screen sends the final games when the match ends. If they match, the result is
  saved at once; if they don't, nothing is saved and both see "the two screens disagreed" (logged in
  `public.disputes`). If the guest's screen never confirms (e.g. it closed), the host's result is saved after 10 s more.
- **Margin factor** = 0.9 + 0.25 × ((share of points the winner won − 0.5) ÷ 0.5), clamped to 0.9–1.15. A retirement
  counts the points played so far.
- **Daily friend cap** is per pair over the last 24 hours. The 4th match still plays; it just doesn't change ratings.
- **Rating breakdown** on the result screen: "N from the ratings × margin × 0.75 friend match".
- **Promotion/demotion** is shown the next time you open your stats (the bar flashes and a toast says so).
- **Players online** counts each account (or guest tab) once, at its busiest state (match > room > queue > menu),
  over the last 70 s. Pages beat every 25 s and go quiet after 2 minutes in a background tab. Up to 2 sockets per
  account; extra ones are closed.
- **Chat:** one line every 3 seconds (both sending and, for older pages, receiving); "Online chat: Hide" in
  Settings hides the other player's lines.
- **Points by shot type** on the result screen: smash, net-shot and drop winners (from the shot that won the point).

## Release order (important)

1. Supabase → SQL Editor: run `supabase/2.7-ranks.sql`, then `supabase/roster.sql`. Optional: `supabase/cleanup-test-accounts.sql`.
2. Deploy the room server: `cd server && PATH="$HOME/.local/node22/bin:$PATH" npx wrangler deploy` (adds the
   `Presence` object, migration v3).
3. Push the game. If the game goes out first, everything still works (ratings fall back to the old calculation,
   the online count shows "--", friend rooms don't count), it just waits for steps 1–2.

## Character balance simulations

Run in the dev preview with `scripts/sim/char-sim.ts` and the synthetic roster `scripts/sim/test-roster.json`
(neither is imported by the game). Hard CPU vs hard CPU, one game to 21, sides swapped every game.

Counts were cut down to fit the time (the machine ran each game in about 4 s with 7 at once): 200–400 games per
test, 12 per round-robin pair. Win rates have wide error bars at these counts, so the point share is the better
measure (±1% or so).

**What it showed.** Power was a trap: Power 35 won 9% of games. Switching parts of Power off showed why (72 games each):
all on 11%, smash speed off 6%, clear depth off 47%, both off 43%. Deeper clears were aimed past the 6.2 m clear line
towards the baseline (6.7 m) and about half went out. The faster smash (up to +7%) never made up for it. This also
explains the round robin: every Power-heavy test character finished bottom.

**Fix.** Power can push a clear only as deep as 6.3 m (`SHOTS.backCourt.powerDeepMax`); shorter clears for low Power
are unchanged. Neutral stats are untouched (the code is skipped when the multiplier is 1).

**Checks.** Neutral: the neutral character plays the same as no character code (52%/50.5% points, within noise).

**Owner's decision (13 Nov 2026): keep stats subtle.** With the current per-point values, a Champion's +10 budget
points are worth about 0–1% of points in CPU vs CPU play, so stats are flavour more than power. `PER_POINT` stays as it is.
